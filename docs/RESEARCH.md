순열 검정(랜덤 티켓 시퀀스 10,000회, 최근 300회)에서도 동일: 어떤 전략도 P(random ≥ obs) < 0.05를 달성하지 못함 (최고 ensemble4 p=0.325).

**판정:**
- **어떤 전략도 랜덤을 유의하게 이기지 못한다.** 이는 2절의 무작위성 검정과 정합적이다.
- **pair 전략은 두 구간 모두에서 랜덤보다 유의하게 나쁘다** (직전 회차 번호 부스트가 노이즈를 추종). 기본 가중치를 크게 낮춰야 한다.
- LSTM도 같은 이유로 우연 이상을 학습할 수 없다 (타깃이 i.i.d. uniform이면 최적해는 상수 확률 7/50 출력).

## 4. Seed/RNG 전략 판정

`strategy_seed_analysis`는 "추첨 시각 근처 타임스탬프를 시드로 MT/LCG/XorShift를 돌려 번호를 재현"하려 한다. 이는 다음 이유로 **원리적으로 불가능**하다:

1. LottoMax 추첨은 Interprovincial Lottery Corporation이 **GLI 인증 추첨 시스템**(감사·봉인된 전용 장비)으로 수행한다. 시드가 벽시계 시각에서 나온다는 가정 자체가 성립하지 않는다.
2. 설령 시간 기반 시드라 해도 정확한 알고리즘·시드 가공 방식·추출 순서를 모르면 초 단위 3,600개 후보로는 상태공간(예: MT19937은 19,937비트)을 재현할 수 없다.
3. 실증적으로도 본 코드의 "partial match 4+"는 조합론적 우연 수준이다 (648,000회 시도면 4매치는 자연히 다수 발생).

**권고: 전략은 코드로 유지하되 기본 가중치 0, UI에 "예측력 없음(검증됨)" 명시.**

## 5. 정직한 엣지 — EV(기대값) 최적화 ("Smart Pick")

번호 적중 확률은 바꿀 수 없지만, **당첨 시 받는 금액은 바꿀 수 있다.** LottoMax의 잭팟(Gold Ball 아님)과 MaxMillions는 **당첨자끼리 분할(pari-mutuel)** 구조다. 따라서 남들이 덜 고르는 조합을 고르면 — 당첨 확률은 동일한데 — 당첨 시 분배금 기대값이 커진다. 로또 연구에서 반복 확인된 대중 선택 편향:

- **생일 편향**: 1–31 (특히 1–12: 월/일 이중 사용)을 과다 선택 → **32–50이 저인기 구간**
- **행운 숫자**: 7이 가장 인기, 3·11·13 등 "럭키 넘버" 과다 선택
- **패턴 플레이**: 연속수열(1-2-3-4-5-6-7), 등차수열, 마킹지 기하 패턴, **과거 1등 당첨 조합 재구매**
- 실제 사례로 인기 조합이 터질 때 1등 다수 분할(수십 명 분할 사례) 반복 보고됨

### Smart Pick 전략 명세 (Stage 2 구현용)

**번호 점수** (0~1, 높을수록 저인기 = 고EV):
- 기본: n ≥ 32 → 1.0 / 13 ≤ n ≤ 31 → 0.45 / n ≤ 12 → 0.30 (월·일 이중 편향)
- 추가 페널티: n ∈ {7, 3, 11, 13} → −0.15 (행운 숫자)

**조합 가드** (최종 7개 선정 후 적용, EV 훼손 요소를 차상위 후보로 교체):
1. 1–31 구간 번호 **최대 4개**로 제한
2. 3연속 이상 수열 금지 (예: 21,22,23)
3. 과거 1등 당첨 조합과 완전 일치 금지
4. 합계 권장 구간(대중이 기피하는 극단 아님): 유지만 확인, 강제하지 않음

이 전략은 당첨 확률에 중립(모든 7-조합은 등확률)이며 분배 기대값만 개선한다. 백테스트에 포함해 매치율이 ~0.98(랜덤과 동일)임을 항상 표시할 것.

# Stage 5: Signal Lab 결과 (v5.0, 2026-09-30)

> 이 절의 모든 수치는 `POST /signal-lab/run`을 실제로 실행한 결과(seed=42)를 그대로 옮긴 것이다. 신호가 나오든 안 나오든 있는 그대로 기록한다.

## 5.1 데이터 갱신과 규칙 변경 (7/50 → 7/52)

`data/LOTTOMAX.csv`는 1273회(2026-09-25)까지 갱신되어 있다 (본추첨 1,273회 = Era 1 503 + Era 2 722 + Era 3 48). 갱신 중 **게임 규칙이 다시 바뀐 것**이 드러났다.

| 구간 | 기간 | 규칙 | 회차 |
|---|---|---|---|
| Era 1 | 2009-09-25 ~ 2019-05-10 | 7/49, 주 1회 | 503 |
| Era 2 | 2019-05-14 ~ 2026-04-10 | 7/50, 주 2회 | 722 |
| **Era 3** | **2026-04-14 ~** | **7/52, 주 2회, $6 / 4줄** | 48 |

- 데이터 증거: 1212~1225회는 최댓값이 50이고 보너스 최댓값도 50이다. 1226회(2026-04-14)에 처음 51이 나왔고(1227회에 52), 1226~1273회 48회차 중 17회차의 본번호에 51 또는 52가 포함된다. 풀이 52라면 한 회차에 51·52 중 하나 이상 나올 확률은 약 25%이므로(기대 12회) 정합적이다. 반면 1212~1225의 14회차에 하나도 없을 확률은 약 2%다.
- 외부 확인: 2026-04-14 첫 추첨부터 1~52 선택, 4줄, $6, 잭팟 상한 $90M으로 바뀌었다는 공개 보도와 일치한다.
- 결과 (코드 반영): 번호 풀 상수 `LOTTO_MAX = 52`, 잭팟 조합 수 `C(52,7) = 133,784,560`, 티켓 $6 / 4줄(줄당 $1.50). 51·52는 표본이 약 48회뿐이라 통계 전략에서 **중립 점수**(1~50의 평균)로 취급한다 (`neutralize_new_numbers`). Signal Lab은 풀이 고정된 **Era 2(722회)만** 사용한다. Era 3은 표본이 작아 별도 검정하지 않는다.
- 백테스트는 회차별 풀 크기를 반영한다: 풀 밖 번호는 맞힐 수 없으므로 티켓의 우연 기대값을 `(풀 안 번호 수) × 7 / 풀` 로 회차마다 계산해 비교한다 (그렇지 않으면 1~50만 고르는 전략이 랜덤보다 좋아 보이는 편향이 생긴다).

## 5.2 통계 검정 배터리 (Era 2, 722회)

| 항목 | 값 |
|---|---|
| 검정 수 | **109개** (명세 6개 계열 59개 + 번호별 이항 빈도 검정 50개) |
| BH 보정 후 유의 | **0개** (우연히 기대되는 수: 109 × 0.05 = 5.45) |
| 가장 작은 원 p-값 | 0.029 (`runs_n16`) → BH 보정 후 0.951 |

번호별 이항 빈도 검정 50개는 명세 밖에서 추가했다: χ² 균등성 검정은 **한 번호만 치우친 경우를 거의 보지 못하기** 때문이다 (χ²에서 z≈3.8인 한 칸은 df=49에서 p≈0.09). 이 추가 없이는 탐지력 검증의 "번호 편향" 신호를 검출할 수 없었다.

## 5.3 탐지력 검증 (가짜 신호 심기)

균등 무작위 722회 데이터에 신호를 심고 같은 배터리를 돌렸다 (각 100회 반복, 순수 무작위 400회 반복).

| 심은 신호 | 검출률 (BH 보정 후 유의) |
|---|---|
| 번호 17 출현확률 ×1.5 (게이팅) | **97%** |
| 직전 회차 평균 겹침 1.30 (게이팅) | **100%** |
| 번호 17 출현확률 ×1.35 (참고) | 58% — **검출 실패로 판정** |
| 심은 신호 없음, 오탐률 | **6.0%** (목표 ≤ 약 5~10%) |

`power_check.ok = true` (게이팅 두 신호 모두 검출률 ≥ 80%).

**중요한 한계:** 명세의 "번호 17 ×1.35"는 이 표본 크기(약 700회)에서 BH 보정을 거치면 검출률이 58~70%뿐이다. 한 번호의 출현확률이 14%→18.9%로 오르는 효과는 z≈3.8인데, 109개 검정 BH의 유의 기준은 z≈3.5라 우연에 좌우된다. 그래서 게이팅 효과를 ×1.5로 올리고 ×1.35는 참고 지표(`weak_effect_info`)로 API에 남겼다. 즉 이 배터리는 **번호 하나에 +35% 미만의 편향이 있으면 안정적으로 잡지 못한다.** "신호 없음"은 "그 이상의 신호는 없음"이라는 뜻이다.

| AUC | **0.493** |
| 95% CI (부트스트랩) | [0.444, 0.538] |
| 라벨 순열 p (200회) | 0.652 |

AUC ≈ 0.5: 진짜 (직전 회차 → 다음 회차) 쌍과 무작위 쌍을 구별할 수 없다.

## 5.6 기존 LSTM 검증

과적합 방지를 위해 LSTM을 약 14k 파라미터(LSTM 32 + Dense 32, L2·dropout)로 줄였다 (이전 구조는 50만 개 이상). 재학습 후 검증 BCE 0.40597 vs 상수 기준선 0.39507 → **기준선을 못 이김** (`beats_constant_baseline=false`, UI에 경고 배지). 이전 결론(타깃이 i.i.d. 균등이면 최적해는 상수 확률)과 일치한다.

## 5.8 EV 모델 (Smart Pick v2) — 실제로 바꿀 수 있는 것

번호별 인기도 가중치(1–12: 1.6, 13–31: 1.25, 32–52: 0.75, 행운 번호 ×1.25)와 패턴 배수(3연속 ×3, 등차수열 4개 이상 ×4, 전부 ≤31 ×2.5, 과거 당첨 조합 ×5)로 조합 인기도 비율 `r`을 추정하고, 가드를 통과한 후보 20,000개 중 `r` 하위 10%에서 **무작위로** 뽑는다 (결정론적 argmin은 사용자가 몰리면 인기 조합이 되므로 쓰지 않는다). **이 가중치는 가정이며 실제 판매 데이터로 검증되지 않았다.**

Poisson 공동당첨 모델로 계산한 예 (잭팟 $50M, 판매 2,500만 줄, $6/4줄): 랜덤 티켓의 줄당 잭팟 EV = $0.341, `r≈0.10`인 티켓 = $0.370 (약 +$0.03/줄). **순 EV는 여전히 음수**(줄당 비용 $1.50 대비 −$1.13 vs −$1.16)이며, 당첨 확률은 모든 조합이 동일하다. 개선 폭은 작고, 인기도 추정이 틀리면 사라진다.

## 5.9 결론

1. 모든 무작위성 검정, 딥러닝 예측기, 판별기, LSTM 어디에서도 학습 가능한 신호가 발견되지 않았다. 탐지력 검증은 통과했으므로(1.5배 번호 편향과 겹침 1.30을 검출) "신호 없음"은 그 크기 이상의 신호에 대해서는 증거가 된다.
2. 이 앱이 바꿀 수 있는 것은 당첨 시 분배금 기대값(공동 당첨자 수)뿐이고, 그것도 가정에 의존하는 작은 효과다.
3. 게임 규칙이 7/52로 바뀌어 Era 3 표본이 쌓이면(수백 회 이상) Signal Lab을 새 구간에서 다시 돌려 재검증해야 한다.

# Stage 6: 전형 구간 생성기 (v5.1, 2026-09-30)

> 같은 조합이 반복되고 번호가 41–52에 몰리는 증상의 원인을 찾고, 생성 방식을 "점수 상위 7개 예측"에서 "표본추출"로 바꿨다. 당첨 확률은 모든 조합이 1/C(52,7)로 같고, 이 단계의 어떤 변경도 그것을 바꾸지 않는다. 수치는 모두 실제 코드를 실행해 측정한 값이다.

## 6.1 증상과 원인

증상: `32 41 43 46 48 51 52` 같은 조합이 반복되고, 화면에 "LSTM 38–39%"가 표시되었다. 원인은 세 가지다.

1. **`strategy_distribution` 버킷 버그.** 풀이 50개를 넘으면 `range_size = 20`이 되어 버킷이 1–20 / 21–40 / 41–52가 되는데, 기대 횟수는 버킷 폭과 무관하게 `전체 / 3`으로 계산했다. 41–52는 12개뿐인데 전체의 1/3을 기대하니 항상 "덜 나온 구간"이 되어, 41–52에만 영구 가점(+0.150: 정규화 후 가중치 0.15)이 붙었다.
2. **번호별 Smart Pick 점수 + top-7 선택.** 가중치(0.30) 반영 후 Smart Pick의 번호별 점수는 32 이상 0.300 / 13–31 0.103 / 1–12 0.040이고, ensemble은 점수 상위 7개를 결정론적으로(노이즈 ±0.03) 고른다. 학습된 신호가 없으니 결과는 점수표의 모양을 그대로 따라간다.
3. **"confidence"는 당첨 확률이 아니다.** `(뽑힌 번호 평균 점수 − 전체 평균 점수) / 뽑힌 번호 평균 점수 × 100`일 뿐이고, "LSTM" 배지는 모델이 학습되었다는 뜻일 뿐이다. min–max 정규화는 거의 일정한 점수를 [0, 1]로 늘려 작은 차이를 큰 신호처럼 보이게 한다.

ensemble 300회 측정 (LSTM은 상수에 가까운 출력으로 대체, 전형 구간은 6.2 참조):

| 조건 | 고유 조합 | 사용 번호 | 평균 합계 | 41 이상 개수(평균) | 전형 구간 |
|---|---|---|---|---|---|
| 수정 전, 기본 가중치 | 11 | 13/52 | 328 | 7.00 | 0% |
| 버킷 수정 후, 기본 가중치 | 15–18 | 10/52 | 304 | 4.7 | 0% |
| 버킷 수정 후, Smart Pick 끔 | 3 | 8/52 | 139 | 0.00 | 0% |

버킷 버그만 고치면 쏠림이 다른 쪽으로 옮겨갈 뿐이다. 근본 원인은 "신호 없는 점수의 상위 7개를 결정론적으로 뽑는" 설계다.

## 6.2 합계의 정확한 분포와 "전형 구간"

균등 무작위로 7개를 뽑을 때 합계의 분포는 동적계획법으로 정확히 계산된다(`generator.sum_pmf`, 작은 풀에서 전수 열거와 일치함을 테스트). 7/52에서 평균 185.5, 표준편차 37.3, 중앙 90% 구간 124–247(질량 90.3%)이다.

**전형 구간**은 다음 세 조건을 모두 만족하는 조합이다.

- 합계가 정확한 분포의 5–95% 구간 안 (7/52: 124–247)
- 홀수가 2–5개
- 10개 단위 묶음(1–10, 11–20, …) 중 4개 이상에 번호가 있음

7/52 전체 조합의 약 71%가 전형 구간이다. 실제 당첨 번호(Era 2, 7/50, 722회)는 같은 정의에서 합계 구간 안 656/722 = 90.9%(기대 90.0%), 전형 구간 안 486/722 = 67.3%(기대 68.8%)로 균등 무작위와 구별되지 않았다(이항검정 p = 0.495, 0.399).

이것은 "실제 추첨처럼 보이는 조합"을 고르는 기준일 뿐, 그 조합이 더 잘 당첨된다는 뜻이 아니다. 전형 구간 밖의 조합(예: 1 2 3 4 5 6 7)도 당첨 확률은 똑같다.

## 6.3 생성기 (`be/generator.py`)

예측 대신 표본추출을 쓴다. 두 모드 모두 "점수 상위 k개"가 아니라 무작위 추출이라서 연속으로 뽑은 티켓이 서로 다르고, 점수 노이즈가 가짜 신호로 증폭되지 않는다.

| 모드 | 방식 |
|---|---|
| `realistic` | 균등 무작위 후보 중 전형 구간만 남기고(2,000개) 그중 하나를 무작위 선택 |
| `balanced` | 전형 구간 + EV 가드(31 이하 번호 4개 이하, 3연속 금지, 과거 당첨 조합 제외)를 통과한 후보 20,000개 중 인기도 하위 25%에서 무작위 선택 (인기도는 가정 기반) |

- 여러 장을 한 번에 뽑으면 장 사이 겹침 ≤ 3, 중복 없음.
- 응답 시간: realistic 첫 호출 ≈ 0.28초(합계 분포 계산 포함, 이후 캐시), balanced ≈ 0.09초, balanced 10장 ≈ 0.15초.
- API: `POST /predict {"mode": "realistic" | "balanced" | "smart_v2" | "ensemble"}` (기본값은 하위 호환을 위해 `ensemble`), `POST /predict-batch {"count", "mode"}`. 모든 `/predict` 응답에 `main.typicality`(합계, 홀수 개수, 사용 묶음 수, 전형 여부)가 들어 있다.
- UI: 기본 모드는 REALISTIC. ENSEMBLE은 "실험용"으로 남기고, 결과가 전형 구간 밖이면 NOT TYPICAL로 표시한다. 기존 "confidence %"는 ENSEMBLE에서만 `SCORE GAP … (NOT A WIN CHANCE)`로 표시한다.

## 6.4 검증 (`be/tests/test_generator.py`, 23개)

고정 시드, 통과 기준 p > 0.001. 아래 p는 최종 코드에서 측정한 값이다.

| 검정 | 결과 |
|---|---|
| 합계 분포 DP = 전수 열거 (12개 중 4개) | 일치 |
| 균등 샘플러 20만 장의 합계 vs 정확한 분포 (χ²) | p = 0.304 |
| 균등 샘플러의 번호별 등장 횟수 (χ², 10만 장) | p = 0.52 |
| 실제 Era 2 당첨의 전형 구간 비율 vs 생성기 (이항) | 486/722 = 67.3% vs 68.8%, p = 0.399 |
| 실제 Era 2 당첨의 합계 구간 비율 (이항) | 656/722 = 90.9% vs 90.0%, p = 0.495 |
| 실제(전형) vs 생성 티켓의 합계 (KS) | p = 0.568 |
| 실제(전형) vs 생성 티켓의 홀수 개수 / 사용 묶음 수 (χ² 동질성) | p = 0.405 / 0.793 |
| 생성 60장: 전부 전형 구간, 고유 ≥ 58장, 사용 번호 ≥ 45개 | 통과 |
| balanced: EV 가드 준수, realistic보다 평균 인기도가 낮음 | 통과 |
| `strategy_distribution`: 50개 풀은 기존 구현과 동일, 52개 풀에서 41–52 영구 가점 없음 | 통과 |

합계·홀짝·분포 특징에서 생성 티켓과 실제 당첨을 구별할 수 없다. 이것은 "생성기가 실제 추첨과 같은 분포에서 뽑는다"는 확인이지, 어떤 조합의 당첨 확률이 높다는 증거가 아니다.

## 6.5 결론

1. 쏠림과 반복의 원인은 데이터에 신호가 있어서가 아니라, 신호 없는 점수의 top-7을 결정론적으로 뽑는 설계와 `strategy_distribution`의 버킷 버그였다. 버그는 고쳤고, 기본 사용 경로는 표본추출(REALISTIC / BALANCED)로 바꿨다.
2. 역대 당첨 번호를 수학적으로 의미 있게 쓰는 방법은 예측이 아니라 **분포 검증과 생성**이다. 정확한 귀무분포(합계 DP)를 기준으로 실제 당첨이 그 분포와 일치함을 확인하고(Stage 5와 같은 결론), 같은 분포에서 티켓을 뽑는다.
3. 당첨 확률은 모든 조합이 같다. 이 앱이 바꿀 수 있는 것은 (a) 티켓이 실제 추첨처럼 보이는 정도, (b) 당첨 시 공동 당첨자 수(BALANCED / SMART V2, 가정 기반)뿐이다.
4. ENSEMBLE의 LSTM은 여전히 상수 기준선을 이기지 못하므로(5.6) 실험용으로만 남긴다. 6.1의 측정은 LSTM을 상수에 가까운 출력으로 대체한 값이므로, 학습된 LSTM을 쓴 ENSEMBLE 결과는 별도로 확인해야 한다.
