# Stage 1 리서치 보고서 — LottoMax 데이터 분석 & 전략 검증

> 작성: 리서치 파이프라인 (Stage 1). 모든 수치는 `data/LOTTOMAX.csv` (본추첨, SEQUENCE NUMBER == 0) 전수 분석 결과이며, 분석 스크립트는 walk-forward 방식으로 `be/app.py`의 전략을 충실히 재구현해 실행했다.

## 1. 데이터 사실 (Data Facts)

| 항목 | 값 |
|---|---|
| 본추첨 회차 수 | **1,211회** (2009-09-25 ~ 2026-02-20) |
| 게임 규칙 변경 | **7/49 → 7/50, 504회차(2019-05-14)부터** |
| 변경 전 (Era 1) | 503회, 주 1회(금요일), 번호 1–49 |
| 변경 후 (Era 2) | 708회, 주 2회(화·금), 번호 1–50 |
| 데이터 무결성 | 회차 중복 없음, 모든 회차 7개 고유 번호 ✅ |

**핵심 발견 — 시대(era) 편향:** 번호 50은 2019-05-17(505회차)에 처음 등장했다. 전체 이력 기준 출현 횟수는 #50 = 99회 vs #1–49 평균 = 171회. 즉 **전체 이력으로 빈도/갭을 계산하는 현재 코드는 #50(및 후반 번호 통계)을 구조적으로 왜곡**한다. 반면 Era 2만 보면 #50 = 99회 vs 기대값 99.1회로 정확히 정상이다. → 통계 전략은 **Era 2(504회차 이후)만 사용해야 한다.**

## 2. 무작위성 검정 (시대별)

| 검정 | Era 1 (7/49) | Era 2 (7/50) | 판정 |

| 연속 회차 반복 (vs 초기하 기대 7²/N) | 평균 1.032 vs 1.000, p=0.404 | 평균 1.014 vs 0.980, p=0.290 | 무상관 ✅ |

**결론: 추첨 데이터는 모든 검정에서 완전한 무작위(uniform, memoryless)와 일치한다.** 학습할 패턴 자체가 존재하지 않는다.

## 3. 전략 백테스트 (walk-forward, 실제 코드 재현)

각 회차 t에서 `draws[:t]`만 입력으로 각 전략의 top-7을 뽑아 실제 회차와 매치 수를 측정. 우연 기대값 = 7×7/50 = **0.98개**.

### 최근 300회

| 전략 | 평균 매치 | t | p | 매치 분포 (0/1/2/3+) |
|---|---|---|---|---|
| frequency | 0.933 | −0.99 | 0.325 | 101/128/61/10 |
| gap | 0.957 | −0.47 | 0.640 | 102/124/60/14 |
| **pair** | **0.867** | **−2.55** | **0.011** | 103/142/47/8 |
| distribution | 0.990 | 0.21 | 0.835 | 92/131/66/11 |
| ensemble(4) | 1.003 | 0.47 | 0.642 | 98/116/74/12 |
| random 기준선 | 0.982 | — | — | — |

### Era 2 전체 (708회)

| 전략 | 평균 매치 | t | p |
|---|---|---|---|
| frequency | 0.928 | −1.68 | 0.094 |
| gap | 1.006 | 0.78 | 0.437 |
| **pair** | **0.911** | **−2.28** | **0.023** |
| distribution | 0.979 | −0.04 | 0.970 |
| ensemble(4) | 0.982 | 0.05 | 0.959 |

순열 검정(랜덤 티켓 시퀀스 10,000회, 최근 300회)에서도 동일: 어떤 전략도 P(random ≥ obs) < 0.05를 달성하지 못함 (최고 ensemble4 p=0.325).

**판정:**
- **어떤 전략도 랜덤을 유의하게 이기지 못한다.** 이는 2절의 무작위성 검정과 정합적이다.
- **pair 전략은 두 구간 모두에서 랜덤보다 유의하게 나쁘다** (직전 회차 번호 부스트가 노이즈를 추종). 기본 가중치를 크게 낮춰야 한다.
- LSTM도 같은 이유로 우연 이상을 학습할 수 없다 (타깃이 i.i.d. uniform이면 최적해는 상수 확률 7/50 출력).

## 4. Seed/RNG 전략 판정

`strategy_seed_analysis`는 "추첨 시각 근처 타임스탬프를 시드로 MT/LCG/XorShift를 돌려 번호를 재현"하려 한다. 이는 다음 이유로 **원리적으로 불가능**하다:

1. LottoMax 추첨은 Interprovincial Lottery Corporation이 **GLI 인증 추첨 시스템**(감사·봉인된 전용 장비)으로 수행한다. 시드가 벽시계 시각에서 나온다는 가정 자체가 성립하지 않는다.
2. 설령 시간 기반 시드라 해도 정확한 알고리즘·시드 가공 방식·추출 순서를 모르면 초 단위 3,600개 후보로는 상태공간(예: MT19937은 19,937비트)을 재현할 수 없다.
3. 실증적으로도 본 코드의 "partial match 4+"는 조합론적 우연 수준이다 (648,000회 시도면 4매치는 자연히 다수 발생).

**권고: 전략은 코드로 유지하되 기본 가중치 0, UI에 "예측력 없음(검증됨)" 명시.**

## 5. 정직한 엣지 — EV(기대값) 최적화 ("Smart Pick")

번호 적중 확률은 바꿀 수 없지만, **당첨 시 받는 금액은 바꿀 수 있다.** LottoMax의 잭팟(Gold Ball 아님)과 MaxMillions는 **당첨자끼리 분할(pari-mutuel)** 구조다. 따라서 남들이 덜 고르는 조합을 고르면 — 당첨 확률은 동일한데 — 당첨 시 분배금 기대값이 커진다. 로또 연구에서 반복 확인된 대중 선택 편향:

- **생일 편향**: 1–31 (특히 1–12: 월/일 이중 사용)을 과다 선택 → **32–50이 저인기 구간**
- **행운 숫자**: 7이 가장 인기, 3·11·13 등 "럭키 넘버" 과다 선택
- **패턴 플레이**: 연속수열(1-2-3-4-5-6-7), 등차수열, 마킹지 기하 패턴, **과거 1등 당첨 조합 재구매**
- 실제 사례로 인기 조합이 터질 때 1등 다수 분할(수십 명 분할 사례) 반복 보고됨

### Smart Pick 전략 명세 (Stage 2 구현용)

**번호 점수** (0~1, 높을수록 저인기 = 고EV):
- 기본: n ≥ 32 → 1.0 / 13 ≤ n ≤ 31 → 0.45 / n ≤ 12 → 0.30 (월·일 이중 편향)
- 추가 페널티: n ∈ {7, 3, 11, 13} → −0.15 (행운 숫자)

**조합 가드** (최종 7개 선정 후 적용, EV 훼손 요소를 차상위 후보로 교체):
1. 1–31 구간 번호 **최대 4개**로 제한
2. 3연속 이상 수열 금지 (예: 21,22,23)
3. 과거 1등 당첨 조합과 완전 일치 금지
4. 합계 권장 구간(대중이 기피하는 극단 아님): 유지만 확인, 강제하지 않음

이 전략은 당첨 확률에 중립(모든 7-조합은 등확률)이며 분배 기대값만 개선한다. 백테스트에 포함해 매치율이 ~0.98(랜덤과 동일)임을 항상 표시할 것.
